# אפיון מוצר – מערכת ניהול השכרת ציוד לאירועים (MVP)

מסמך זה הוא מקור האמת לאפיון המוצר בגרסת ה־MVP. פירוט טכני (סכמת DB, RLS, פעולות שרת): [TECH_DESIGN.md](TECH_DESIGN.md).  
מפת מה קיים בקוד ובממשק: [BUILT.md](BUILT.md).

---

## הקשר והנחות ארגוניות

- **תחום**: ניהול השכרת ציוד לאירועים, לפי מסמכי אפיון ומבנה ארגוני של החברה.
- **טננט**: **חברה אחת (טננט יחיד)** – אין הפרדת נתונים בין חברות; פישוט RLS וסכמה.
- **צוות שטח (MVP)**: אותה אפליקציית **Next.js** – ממשק **רספונסיבי** ו־**PWA** (מסכים ייעודיים למובייל), ללא אפליקציה נפרדת בשלב זה.
- **שפת ממשק**: עברית בלבד, **RTL** מלא (ראו גם `docs/CONVENTIONS.md`).

## תפקידים במערכת (Roles)

| תפקיד | תיאור |
| --- | --- |
| **מנהל מערכת (Admin)** | גישה מלאה לכל המודולים, הגדרות, דוחות פיננסיים וניהול הרשאות. |
| **משרד / שיווק** | ניהול לידים, לקוחות, הפקת הצעות מחיר וניהול גבייה. |
| **מנהל תפעול / פרויקטים** | שיבוץ עובדים, תכנון הובלות, **לוח זמנים בסיסי** (תאריכים/סטטוסים; ללא תלויות משימות מלאות ב־MVP) וסיורי שטח. |
| **מנהל מחסן** | ניהול מלאי, ליקוט ציוד, טעינת משאיות ובדיקת ציוד חוזר. |
| **צוות שטח** | צפייה בסידור עבודה, דיווח שעות, עדכון סטטוס הקמה/פירוק (מובייל / PWA). |

---

## יכולות MVP קריטיות

1. **ניהול לקוחות (CRM)** – מאגר לקוחות עם היסטוריית פרויקטים.
2. **ניהול מלאי מדויק** – מעקב אחר ציוד במחסן מול ציוד משובץ/בשימוש באירועים; ב־MVP העדכון הוא **לאחר פעולות** (שמירה, ליקוט וכו'). **Supabase Realtime** מתוכנן לשלב 2 אם יידרש.
3. **מערכת הצעות מחיר** – הפקת הצעה הכוללת ציוד, כוח אדם והובלה.
4. **לוח פרויקטים** – מעקב סטטוסים: הצעה → מאושר → בהכנה → בהקמה → בפירוק → סגור.
5. **שיבוץ עובדים** – ניהול צוותים (קבועים, לפי שעות, קבלנים) ושיוכם לפרויקט.

## טופס לקוח – פרטי אירוע (קבלת פנייה)

לקוח שמבקש אירוע ממלא טופס עם השדות הבאים. השדות משמשים את משרד/תפעול להמשך תמחור, הצעה ותכנון לוגיסטי.

| שדה | הערות |
| --- | --- |
| תאריך הקמה + שעות | נדרש לוגיסטיקת הקמה; לאשר מול UX אם טווח שעות או נקודת זמן אחת. |
| תאריך אירוע + שעות | לוגיסטיקת האירוע עצמו. |
| תאריך פירוק + שעה | פירוק לאחר האירוע; לאשר אם שעה בודדת או טווח. |
| תמונות של השטח | קבצי תמונה; אחסון מאובטח (למשל Supabase Storage). |
| סקיצה | קובץ / תמונה; אותו מנגנון אחסון כמו תמונות. |
| דרכי גישה | טקסט (הנחיות גישה לשטח). |
| צבע חיפוי | טקסט חופשי או רשימת ערכים מוגדרת מראש (להחליט במימוש). |
| הערות | טקסט חופשי. |
| כתובת האירוע | כתובת מלאה; אפשרות עתידית לפירוט עיר/רחוב או מפה בשלב 2. |

### מי ממלא את הטופס (MVP)

- **שני מסלולים**:
  1. **הלקוח** – מילוי עצמי (למשל דף ציבורי או קישור ייעודי; מדיניות גישה ואימות יוגדרו במימוש).
  2. **משרד / שיווק** – הזנה ועריכה בשם הלקוח באותם שדות.

דרישות נלוות: ולידציה וסניטיזציה בצד שרת, מדיניות קבצים (גודל/סוג), **RLS** ומדיניות **Storage** המבדילים בין יצירה עצמית של לקוח לבין עריכה פנימית.

### כללי ולידציה עסקיים (מומלץ)

- סדר לוגי של תאריכים: הקמה ≤ אירוע ≤ פירוק (או לפי כללי עסק שיוגדרו).
- שמירה על קישור ל־**לקוח** (או ליד) ול־**פרויקט טיוטה** לפני שלב תמחור והצעה.

## זרימת משתמש עיקרית (User Flow)

1. **קבלת פנייה** – הזנת פרטי לקוח ודרישות ראשוניות; שילוב טופס פרטי האירוע לעיל.
2. **תמחור והצעה** – בחירת ציוד מהמלאי ובדיקת זמינות, הוספת עלויות כ״א והובלה, שליחה ללקוח.
3. **אישור הזמנה** – הפיכת הצעה לפרויקט פעיל במערכת.
4. **תכנון לוגיסטי** – שיבוץ מנהל צוות, נהג ופועלים; תכנון מסלול הובלה.
5. **ביצוע** – ליקוט במחסן → העמסה → הקמה בשטח → ניהול אירוע → פירוק.
6. **סגירה** – החזרת ציוד, דיווח חוסרים/שברים, **גבייה ומעקב תשלומים פנימי** (ב־MVP). חיבור/ייצוא חשבונית חיצונית – שלב 2.

| מסך | תיאור |

| **Dashboard** | תמונת מצב יומית: אירועים, חוסרי ציוד קריטיים, גרף הכנסות (לפי היקף שנקבע). |

| **גבייה** | מעקב תשלומים, מקדמות ויתרות חוב. |
| **טופס לקוח / פרטי אירוע** | מסלול ציבורי/לקוח + מסלול פנימי למשרד; אותם שדות, הרשאות שונות. |

## מודל נתונים ראשוני (רמת אפיון)

ישויות עיקריות ל־MVP (שדות לפי האפיון המקורי; שמות טבלאות ופירוט יתועדו בסכמה טכנית):

| ישות | שדות עיקריים |
| --- | --- |
| **Clients** | מזהה, שם, טלפון, דוא״ל, כתובת, היסטוריה (קישור לפרויקטים). |
| **Equipment** | מזהה, שם, קטגוריה, כמות כוללת, מחיר השכרה, מיקום במחסן. |
| **Projects** | מזהה, מזהה לקוח, תאריך(ים), מיקום, סטטוס, מחיר כולל. |
| **Project_Equipment** | מזהה פרויקט, מזהה פריט, כמות. |
| **Employees** | מזהה, שם, סוג (קבוע / לפי שעה / קבלן), תעריף שעתי, זמינות. |
| **Assignments** | מזהה פרויקט, מזהה עובד, תפקיד (ראש צוות / נהג / פועל). |
| **Trucks** | מזהה, מספר רישוי, מזהה נהג, סטטוס. |

**הרחבה נדרשת לטופס הלקוח**: טבלה או קישור לישות (למשל פרטי אתר / פנייה) המכילה את שדות טופס האירוע ונתיבי קבצים (תמונות, סקיצה) ב־Storage.

## הרשאות (Permissions) ו־RLS

- שימוש ב־**Supabase Row Level Security (RLS)** על כל הטבלאות הרלוונטיות.
- **צוות שטח**: רואה **רק** פרויקטים שאליהם הוא משובץ (ולא נתונים רגישים שלא נדרשים לתפקידו).
- **מנהל מחסן / מחסנאים**: יכולים לעדכן בעיקר **כמויות מלאי**, **סטטוס ליקוט** ונתונים הקשורים למחסן – לפי מדיניות מדויקת שתוגדר במימוש.
- **מנהלים (תפעול / מערכת)**: גישה לנתוני **רווחיות** ו־**עלויות עובדים** לפי תפקיד.
- **טופס לקוח וקבצים**: מדיניות נפרדת ליצירה עצמית מול עריכה פנימית; גישה לקבצים רק לתפקידים מורשים.

## קריטריוני קבלה כלליים ל־MVP (תזכורת)

- כל ממשק המשתמש בעברית, RTL תקין.
- טפסים עם ולידציה בצד לקוח ושרת; אין חשיפת שגיאות פנימיות ללקוח.
- סודות ומפתחות רק דרך משתני סביבה; RLS פעיל על נתונים רגישים.
- עקביות ויזואלית ורכיבי UI משותפים לכל המסכים (לפי `docs/CONVENTIONS.md`).
